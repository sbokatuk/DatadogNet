# 3.14.0.4

The Microsoft.Extensions integration becomes its own package, and `DatadogNet.Maui` gains a
Windows stub head — which together remove the last pieces of ceremony this set asked of an app.
The binding pins are unchanged: DatadogNet.iOS `3.14.0.2` (dd-sdk-ios 3.14.0), DatadogNet.Android
`3.12.1.2` (dd-sdk-android 3.12.1), DatadogNet.Mac `3.14.0.1`.

## New: `DatadogNet.Extensions.DependencyInjection`

Everything `UseDatadog` wired into the container now lives in a package with no MAUI in it, so a
plain .NET Android or iOS app, a background service, or a test host gets the same wiring:

```csharp
builder.Services.AddDatadog(new DatadogConfiguration { /* … */ });   // init + registrations
builder.Logging.AddDatadog();                                        // the ILogger provider
builder.Services.AddHttpClient<OrderService>().AddDatadogTracking(); // HttpClient instrumentation
```

`AddDatadog` registers `IRumMonitor`, `IDatadogLogs`, `IDatadogLogger`, `IDatadogTracer` and
`ISessionReplay` as singletons with `TryAdd` semantics (a test host's fake wins); an overload
without the configuration registers without initialising, for apps that initialise the SDK even
earlier. `DatadogNet.Maui` depends on this package and delegates to it — a MAUI app changes
nothing and gets the same behaviour through `UseDatadog`.

**Moves to be aware of** (source-compatible for a typical app, which already has
`using DatadogNet;`):

- `AddDatadogTracking` and `DatadogHttpMessageHandlerOptions` moved from the `DatadogNet.Maui`
  namespace and assembly into `DatadogNet` in the new package.
- The `ILoggingBuilder.AddDatadog(DatadogMauiOptions?)` overload is replaced by
  `AddDatadog(LoggerOptions?, LogLevel)` in the new package; `UseDatadog` passes the MAUI
  options' values through, so only direct callers of the old overload adjust.

## `DatadogNet.Maui` restores on a Windows head

The package now ships `net8.0/net9.0/net10.0-windows10.0.19041.0` stub heads: `UseDatadog`
compiles and runs on a Windows head, and every call lands in the core package's documented no-op
neutral implementation. The platform-conditional `PackageReference` that earlier releases
required for a windows-headed app is no longer needed — every package in the set is referenced
unconditionally.

## Unhandled-exception coverage reaches the platform boundaries

Beyond `AppDomain.UnhandledException` and `TaskScheduler.UnobservedTaskException`, the reporter
now hooks Android's `UnhandledExceptionRaiser` and Apple's managed-exception marshalling (iOS and
Mac Catalyst) — the boundaries where a failure can end the app without ever reaching the
`AppDomain` hook. A weak reported-set ensures a failure seen by more than one hook is one RUM
error, not two.

## Verified harder

- The device tests now exercise `DatadogNet.WebView` on a **real platform web view** — bridge in,
  bridge out, plus the argument contract — where previously the package was never executed
  anywhere.
- The sample gains the missing demonstrations: a tracked WebView page, a `ConfigureNative`
  worked example (one platform-only setting per side), a consent cycle, and the consent-gated
  `StartRecordingImmediately = false` → `StartRecording()` flow.
- The `DatadogNet.WebView` and `DatadogNet.CrashReporting` packages ship the Android R8
  keep-rules for their JNI-only entry points under `buildTransitive/` — the binding packages'
  own rules cannot flow through this set's `exclude=Build` dependencies — asserted by a new
  package test. Six new unit tests cover the DI package's registrations, `TryAdd` semantics,
  provider de-duplication and the HttpClient wiring.

## Release pipeline

nuget.org now shows these notes (`docs/release-notes/<version>.md` packs into
`PackageReleaseNotes`); CI fails when the README's versions drift from `Directory.Build.props` —
the install snippets sat at `3.14.0.1` while `3.14.0.3` shipped, and cannot do that again. The
net8 sunset is stated policy: dropped in the first release after .NET 8 leaves support on
**10 November 2026**, in step with the binding repositories.

## Upgrading from 3.14.0.3

For a MAUI app: nothing to change; optionally delete any windows-head guard around the
`DatadogNet.Maui` reference. Direct callers of the moved HttpClient/logging extensions: see the
moves above.
